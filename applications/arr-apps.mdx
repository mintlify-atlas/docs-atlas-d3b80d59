The "Arr" ecosystem is a collection of applications that automate the search, download, and organisation of different media types. They communicate over the internal Docker network: Prowlarr (or Jackett) feeds indexers to the *arr apps, which instruct download clients to fetch releases, and Autoscan triggers your media server library refresh once files land in the right directory. Saltbox pre-configures each app with the correct paths, SSO middleware, and ThemePark support so you can go from zero to a working automation stack in a single playbook run.

### Sonarr

```bash
ansible-playbook saltbox.yml --tags sonarr
```

Sonarr runs on port `8989` inside the container (`ghcr.io/hotio/sonarr`) and is accessible at `https://sonarr.<your-domain>`. Saltbox enables `sonarr_role_external_auth: true` by default, meaning Traefik's SSO middleware guards the web UI while the API endpoints (`/api`, `/feed`, `/ping`) remain accessible without authentication for Arr-to-Arr communication.

### Radarr

```bash
ansible-playbook saltbox.yml --tags radarr
```

Radarr runs on port `7878` (`ghcr.io/hotio/radarr`) and is accessible at `https://radarr.<your-domain>`. Like Sonarr, `radarr_role_external_auth: true` is set and API paths bypass SSO.

### Prowlarr

```bash
ansible-playbook saltbox.yml --tags prowlarr
```

Prowlarr is the recommended indexer manager for new Saltbox setups. Once deployed, add your indexers in Prowlarr and use its **Apps** sync feature to push them to Sonarr, Radarr, and Lidarr automatically — no per-app manual indexer configuration required.

## Plex Analytics

### Tautulli

Tautulli connects to Plex and records detailed playback history, user statistics, and notification events.

```bash
ansible-playbook saltbox.yml --tags tautulli
```

Tautulli runs on port `8181` (`ghcr.io/hotio/tautulli`) and is accessible at `https://tautulli.<your-domain>`. It uses `tautulli_role_traefik_sso_middleware` (which defaults to `traefik_default_sso_middleware`) so the dashboard is SSO-protected, while notification webhook paths (`/api`, `/newsletter`, `/image`, `/pms_image_proxy`) are exempt.

## Multi-Instance Support

Every major Arr app supports multiple isolated instances via its `_instances` variable. This is useful for running separate 1080p and 4K workflows, or for segregating different users' libraries.

```yaml
# inventory/host_vars/localhost.yml

# Two Sonarr instances: standard and 4K
sonarr_instances:
  - sonarr
  - sonarr4k

# Two Radarr instances: standard and 4K
radarr_instances:
  - radarr
  - radarr4k
```

Each instance gets its own subdomain, appdata directory, and Docker container. Run the tag as normal and Saltbox will deploy all instances in the list:

```bash
ansible-playbook saltbox.yml --tags sonarr
# Deploys both sonarr and sonarr4k
```

## External Authentication

All Arr apps have `_role_external_auth: true` set, which attaches the `traefik_default_sso_middleware` to all non-API routes. This means your Authelia or Authentik SSO session is required to access the web UI, but Radarr/Sonarr API tokens still work for inter-app communication without involving the SSO layer.

```yaml
# These are set automatically — shown here for reference
sonarr_role_external_auth: true
sonarr_role_traefik_sso_middleware: "{{ traefik_default_sso_middleware }}"
sonarr_role_traefik_api_endpoint: "PathPrefix(`/api`) || PathPrefix(`/feed`) || PathPrefix(`/ping`)"
```

## ThemePark Integration

All Arr apps support [Theme.Park](https://github.com/themepark-dev/theme.park) for custom UI theming. Enable it per-app in inventory:

```yaml
sonarr_role_themepark_enabled: true
radarr_role_themepark_enabled: true
lidarr_role_themepark_enabled: true
```

The theme applied is controlled by the global `global_themepark_theme` variable (set in `adv_settings.yml`). Per-app theme overrides are also supported.
